校园失物招领

2026 秋软件工程结对作业（第二次之程序实现）
基于第一次结对作业的墨刀原型，把原型里的 10 个页面逐一实现成可以直接用的网页。

原生 HTML / CSS / JavaScript，零第三方依赖。
不需要 npm install，不需要构建，不需要起服务器 —— 双击 index.html 就能用。

一、使用说明（测试人员看这里）

1. 怎么看网页

  1. 把整个文件夹下载到本地（保持目录结构不变，assets/ 与 src/ 都要在）；
  2. 双击 index.html（或右键 → 打开方式 → Google Chrome）；
  3. 完成。

唯一的环境要求是用谷歌浏览器打开（作业要求里明确的，不同浏览器效果可能不一致）。
数据存在浏览器本机的 localStorage 里，关掉再打开记录还在。
想回到初始的示例数据：浏览器控制台执行 localStorage.clear() 后刷新。

2. 怎么跑单元测试（可选）

两种跑法，用的是同一份用例（tests/cases.js）：

方式怎么做适合谁
命令行项目根目录执行 npm test装了 Node.js（≥ 22）的同学
浏览器用 Chrome 打开 tests/run-browser.html没装 Node 也能跑，结果直接显示在页面上

命令行若报 无法加载文件 ...\npm.ps1，因为在此系统上禁止运行脚本，那是 Windows PowerShell 的默认执行策略挡住了 npm.ps1，与本项目无关。改跑 npm.cmd test 或 node tests/run-node.mjs 即可。

目录为什么这样分

   用户操作
      │
      ▼
   app.js ──────▶ storage/ ──▶ （localStorage / 内存）
      │               ▲
      │               │ 只调规则，不碰界面
      ▼               │
  pages/ + ui/ ──▶ domain/（规则）
  • 依赖方向单向：app → pages/ui → domain，app → storage → domain。

domain/ 里没有任何一行碰 DOM、碰存储、碰网络，所以能被直接单元测试；

  • domain/ 同时被浏览器和 Node 加载：源码写成浏览器能直接 <script> 跑的普通脚本，

测试用 vm.runInThisContext 加载同一批文件，不存在"测试里是副本"而慢慢长歪的风险；

  • 不用 import / export：ES module 在 file:// 协议下会被浏览器的跨域策略拦掉（实测双击直接白屏），

而作业要求"下载后运行 html 就能展现预期结果"，所以只能用普通脚本。

两处需要说明的实现取舍

  1. 状态文案：作业原文要求"由发布者将信息标记为已找到或已归还"，而原型卡片上写的是「已结束」。

本程序取两者之长 —— 进行中统一叫「进行中」，终态按类型区分为「已找到 / 已归还」。

  1. 招领发布：原型只画了「寻物发布页」，但发布页上同时有「我丢失了物品」和「我捡到了物品」两个入口，

所以招领复用同一张表单，只把标题与地点/时间的措辞按类型换掉（丢失 ↔ 拾获）。

  1. 原型上有图标但没有对应流程的东西（首页信封、个人页齿轮、详情页星标与举报）：

按原型画出来，但做成装饰而不是按钮 —— 原型里没有消息页、设置页、收藏列表页、举报流程，
做成能点的按钮就成了"点了没反应"的死控件。个人页的「我的收藏」入口同理，列表恒为空。

四、单元测试说明

135 个用例，命令行与浏览器两种跑法，全部通过。
用例按四类情况铺开：正常 / 边界 / 异常 / 恶意（含 XSS 载荷、正则元字符、重复 id、存储写满、JSON 损坏）。

五、已知限制

  1. 没有登录与实名认证（作业明确不要求）。发布者身份是浏览器本机的固定档案，

据此区分「我的信息」和「别人的信息」，所以不存在真正的安全边界 —— 真上线必须补鉴权。

  1. 数据只在本机：localStorage 不跨设备同步，换电脑看不到自己的记录。
  2. 图片走 base64 存 localStorage，受约 5MB 容量限制，所以上传时限制单张不超过 2MB；

写满时会给出中文提示，不会静默丢数据。

  1. 收藏与举报只有外观：原型里没有对应的列表页与流程，作业正文也明确"不要求"，故未实现。
  2. 本机档案写死在 src/storage/seed.js 的 buildProfile()：没有资料编辑页，改名要改代码。
