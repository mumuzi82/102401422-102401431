# 校园失物招领

> 2026 秋软件工程结对作业（第二次之程序实现）
> 基于第一次结对作业的墨刀原型，把原型里的 **10 个页面**逐一实现成可以直接用的网页。

**原生 HTML / CSS / JavaScript，零第三方依赖。**
不需要 `npm install`，不需要构建，不需要起服务器 —— **双击 `index.html` 就能用**。

---

## 一、使用说明（测试人员看这里）

### 1. 怎么看网页

1. 把整个文件夹下载到本地（**保持目录结构不变**，`assets/` 与 `src/` 都要在）；
2. **双击 `index.html`**（或右键 → 打开方式 → Google Chrome）；
3. 完成。

> 唯一的环境要求是**用谷歌浏览器打开**（作业要求里明确的，不同浏览器效果可能不一致）。
> 数据存在浏览器本机的 `localStorage` 里，关掉再打开记录还在。
> 想回到初始的示例数据：浏览器控制台执行 `localStorage.clear()` 后刷新。

### 2. 怎么跑单元测试（可选）

两种跑法，用的是**同一份用例**（`tests/cases.js`）：

| 方式 | 怎么做 | 适合谁 |
| --- | --- | --- |
| 命令行 | 项目根目录执行 `npm test` | 装了 Node.js（≥ 22）的同学 |
| 浏览器 | 用 Chrome 打开 `tests/run-browser.html` | **没装 Node 也能跑**，结果直接显示在页面上 |

> 命令行若报 `无法加载文件 ...\npm.ps1，因为在此系统上禁止运行脚本`，那是 Windows PowerShell 的默认执行策略挡住了 `npm.ps1`，与本项目无关。改跑 `npm.cmd test` 或 `node tests/run-node.mjs` 即可。

### 3. 十页走一遍的推荐路线

| 想看什么 | 怎么走 |
| --- | --- |
| 首页信息流与三个 Tab | 打开就是；点「全部失物 / 失物寻找 / 失物招领」切换 |
| 搜索与关键词高亮 | 底部「搜索」→ 点「学生证」标签 → 看结果与高亮 |
| 发布一条信息 | 底部「发布」→ 点「我丢失了物品」→ 填表 → 点「点击发布」 |
| 表单校验 | 在发布页**什么都不填**直接点「点击发布」，会逐项标红 |
| 发布成功页 | 正常提交后自动进入 |
| 发布者视角的详情页 | 提交后点「查看发布详情」（可「标记已结束」或「取消发布」） |
| 浏览者视角的详情页 | 回首页，点「电动车钥匙」那张卡 |
| 联系发布者页面 | 在上面那页点底部「联系发布者」 |
| 个人页 | 底部「我的」 |

### 目录为什么这样分

```
   用户操作
      │
      ▼
   app.js ──────▶ storage/ ──▶ （localStorage / 内存）
      │               ▲
      │               │ 只调规则，不碰界面
      ▼               │
  pages/ + ui/ ──▶ domain/（规则）
```

- **依赖方向单向**：`app → pages/ui → domain`，`app → storage → domain`。
  `domain/` 里没有任何一行碰 DOM、碰存储、碰网络，所以能被直接单元测试；
- **`domain/` 同时被浏览器和 Node 加载**：源码写成浏览器能直接 `<script>` 跑的普通脚本，
  测试用 `vm.runInThisContext` 加载**同一批文件**，不存在"测试里是副本"而慢慢长歪的风险；
- **不用 `import` / `export`**：ES module 在 `file://` 协议下会被浏览器的跨域策略拦掉（实测双击直接白屏），
  而作业要求"下载后运行 html 就能展现预期结果"，所以只能用普通脚本。

### 两处需要说明的实现取舍

1. **状态文案**：作业原文要求"由发布者将信息标记为**已找到**或**已归还**"，而原型卡片上写的是「已结束」。
   本程序取两者之长 —— 进行中统一叫「进行中」，终态按类型区分为「已找到 / 已归还」。
2. **招领发布**：原型只画了「寻物发布页」，但发布页上同时有「我丢失了物品」和「我捡到了物品」两个入口，
   所以招领复用同一张表单，只把标题与地点/时间的措辞按类型换掉（丢失 ↔ 拾获）。
3. **原型上有图标但没有对应流程的东西**（首页信封、个人页齿轮、详情页星标与举报）：
   按原型画出来，但**做成装饰而不是按钮** —— 原型里没有消息页、设置页、收藏列表页、举报流程，
   做成能点的按钮就成了"点了没反应"的死控件。个人页的「我的收藏」入口同理，列表恒为空。

## 四、单元测试说明

**135 个用例，命令行与浏览器两种跑法，全部通过。**
用例按四类情况铺开：正常 / 边界 / 异常 / 恶意（含 XSS 载荷、正则元字符、重复 id、存储写满、JSON 损坏）。

| 分组 | 覆盖的函数 |
| --- | --- |
| `schema.check` | 记录结构校验（字段齐不齐、类型对不对、枚举合不合法） |
| `text.segments` | 关键词分段（高亮的数据来源，含 HTML 实体与正则元字符） |
| `text` 时间与联系方式 | `itemTime` / `relativeTime` / `maskContact` |
| `query.matches` | 关键词匹配（空格分隔多词的 AND 语义） |
| `query.filter` | 筛选（类型 / 类别 / 状态） |
| `query.sort` | 排序（含"纯函数不改原数组"） |
| `query.summary` 等 | 统计与计数 |
| `lifecycle` | 状态机：合法迁移、幂等、非法迁移、撤销、纯函数性 |
| `validate.publish` | 表单逐项校验与长度边界 |
| `validate.importPayload` | 备份导入：坏 JSON、缺字段、id 重复 |
| `storage` 适配器 | 种子写入、数据损坏不覆盖、容量写满、导出导入、读改写 |

另有 `scripts/verify-pages.mjs`，用 CDP 驱动真实浏览器按原型逐页走查，
**72 项断言**覆盖十页的结构、字段、文案与一条完整的发布链路（发布 → 成功页 → 详情页 → 标记已结束），
并自动产出 `docs/shots/` 下的截图。

## 五、已知限制

1. **没有登录与实名认证**（作业明确不要求）。发布者身份是浏览器本机的固定档案，
   据此区分「我的信息」和「别人的信息」，所以不存在真正的安全边界 —— 真上线必须补鉴权。
2. **数据只在本机**：`localStorage` 不跨设备同步，换电脑看不到自己的记录。
3. **图片走 base64 存 `localStorage`**，受约 5MB 容量限制，所以上传时限制单张不超过 2MB；
   写满时会给出中文提示，不会静默丢数据。
4. **收藏与举报只有外观**：原型里没有对应的列表页与流程，作业正文也明确"不要求"，故未实现。
5. **本机档案写死在 `src/storage/seed.js` 的 `buildProfile()`**：没有资料编辑页，改名要改代码。
